# pi-observer 使用说明

| 项 | 内容 |
|:--|:--|
| 面向 | 自己用这个看板的人。照着做就行，不需要看代码 |
| 前提 | 桌面应用不需要装任何东西；用命令行跑需要 Node ≥ 24（`< 27`） |
| 边界 | 单用户、单机、只读。服务只监听 `127.0.0.1`，别人从局域网连不上 |
| 别的文档 | 需求与判据看 [prd-v0.2.md](prd-v0.2.md)，技术取舍看 [tech-stack.md](tech-stack.md)，实测数据看 [durable-feasibility.md](durable-feasibility.md) |

## 1. 它是什么

pi-observer 是 Pi 的运行时数据看板。看板上能看到：一个会话里每次模型请求的正文、
工具调用的参数与结果、钩子事件、用量与花费，以及一条按时间排好的时间线。

它只读：不会改你的 Pi 会话文件，不删任何东西。

数据有两个来源：

- **Pi 的会话文件**（`~/.pi/agent/sessions/`）——服务启动时扫一遍，之后每秒跟进新增的条目；
- **探针推来的运行时数据**（模型请求体、工具调用、钩子事件）——探针是装在 Pi 里的一个扩展。

所以「有会话列表」不代表「有请求正文」：后者要探针在跑才有。

## 2. 装桌面应用（日常这么用）

### 2.1 安装

拿到 `pi-observer-<版本>-arm64.dmg` 之后：

1. 双击 dmg；
2. 把 `pi-observer.app` 拖进 `Applications`；
3. 右键点一下挂载出来的磁盘图标，选「推出」；
4. 打开「应用程序」里的 pi-observer。

窗口会自己起来，不用填地址、不用记端口。应用会挑一个空闲端口把服务跑起来。

**如果双击打不开**，提示「无法验证开发者」：右键点应用，选「打开」，再点一次「打开」。
本地自己构建出来的 dmg 不会有这个提示（macOS 只拦从网上下载的文件）。

### 2.2 第一次打开：装探针

应用只是「看板」，真正把运行时数据推过来的是**探针**——一个装在 Pi 里的扩展。装它是一次性的：

1. 在应用里点顶部的「设置」；
2. 找到「探针（Pi 扩展）」那一栏；
3. 点「安装探针」。

这一步会做两件事：把探针代码复制到 `~/.pi-observer/probe/`，并在 Pi 的扩展目录
（`~/.pi/agent/extensions/`）里写一个入口文件。写用户自己的 Pi 配置是有副作用的操作，
所以不会自动装，必须你点一下。

如果那个入口文件已经存在、但不是这个应用装的，应用会先问一句「确认要覆盖吗」，
不会偷偷改掉你手写的东西。

### 2.3 确认装上了

装完探针之后：

- **重开一个 Pi 会话**才会生效。已经在跑的 Pi 不会自动加载新装的扩展。
- 看板右上角那个胶囊会变成「探针已连接 · 刚刚」；没有数据进来时显示「探针静默」。

### 2.4 升级与卸载

**升级**：退出旧应用，用新版本的 dmg 覆盖 `/Applications` 里的那一份。

**卸载**：把 `/Applications/pi-observer.app` 删掉。数据在 `~/.pi-observer/`，默认保留
（重装后历史还在）。要连数据一起清掉，在设置页勾上「卸载时连数据一起删」再点「卸载探针」。

## 3. 用命令行跑

### 3.1 开发

```bash
npm run dev        # http://127.0.0.1:4173
```

改代码会热更新。**注意 dev 模式别和桌面应用同时开**（见 §6.4）。

### 3.2 生产

```bash
npm run build
npm run start
```

`next start` 用的是 `.next/` 里的编译产物。终端关掉服务就没了。

### 3.3 脱离仓库的独立目录

要在一台机器上长期跑、又不想要整个仓库：

```bash
node tools/desktop/prepare.mjs          # 构建 + 裁剪，产物在 desktop/resources/server/
cd desktop/resources/server
PORT=4173 HOSTNAME=127.0.0.1 node server.js
```

这个目录自带依赖，拷到任何装了 Node 24+ 的机器上都能跑。

## 4. 数据在哪儿

### 4.1 看板自己的数据

全在 `~/.pi-observer/`（工程外，不进 git）：

| 东西 | 是什么 | 大概多大 |
|:--|:--|:--|
| `observer.db` | 索引库：会话、条目骨架、事件、工具、请求、用量 | 十几 MB |
| `observer.db-wal` / `-shm` | SQLite 的写前日志与共享内存，跟主库是一套 | 几 MB |
| `payloads/request/` | 模型请求的完整正文（探针写的） | 几十 MB 起 |
| `payloads/message/` | 会话条目的完整正文（服务回填时写的） | 几十 MB 起 |
| `payloads/event/` | 钩子事件的完整正文（探针写的） | 几 MB |
| `probe.json` | 服务告诉探针「我在哪」的地址与路径 | 几百字节 |
| `token` | 写接口的密钥（权限 0600） | 几十字节 |
| `probe.log` | 探针自己的日志 | 几十 KB，轮转 |
| `session-cursor/` | 会话级的序号游标，保证 `--resume` 后序号不重置 | 很小 |

正文是**不自动清理**的：容量由你自己控制，觉得大了就删对应的文件或整个目录。

### 4.2 Pi 的会话文件

`~/.pi/agent/sessions/`——Pi 自己写的，看板只读，不改。

### 4.3 备份与迁移

要备份就拷 `~/.pi-observer/` 整个目录（正文文件都在里面）。换机器时：

1. 把这个目录拷过去；
2. 装上桌面应用；
3. 在设置页装探针。

历史会跟着走。库里存的是正文文件的**相对路径**，所以目录整体搬过去仍然对得上。

### 4.4 看占用

设置页下半部分就是占用统计：数据库多少、正文文件多少、按类型分多少、哪几个会话最占地方。

## 5. 探针

### 5.1 它做什么

探针是 Pi 的扩展，订阅 Pi 的运行时事件，把模型请求体、工具调用、钩子事件批量推给看板。
它只读不改，不往你的会话里写任何东西。

它有自己的队列与退避：服务不可用时数据先攒在内存里（上限 2000 条 / 64 MB），
服务恢复后再补发；实在攒不下就丢弃，并在 `dropped_count` 里记着。

### 5.2 安装

设置页点「安装探针」是最省事的。手动装也可以：

```bash
cp -R ext ~/.pi-observer/probe/ext
cp -R src ~/.pi-observer/probe/src
cat > ~/.pi/agent/extensions/pi-observer.ts <<'EOF'
export { default } from "/Users/<你的用户名>/.pi-observer/probe/ext/index.ts";
EOF
```

Pi 每次启动都会扫描 `<agent-dir>/extensions/` 下的 `.ts` / `.js` 文件并加载。

### 5.3 生效条件

探针在**每个 Pi 会话开始时**读一次配置。所以：

- 装完探针要**重开 Pi 会话**；
- 改了 `~/.pi-observer/probe.json`（比如服务换了端口）也要重开。

但如果只是服务换了端口，探针在推送失败时会自己重读配置并切过去，不用重开。

### 5.4 排查

| 现象 | 看哪里 |
|:--|:--|
| 右上角显示「探针静默」 | 探针没在推：Pi 是重开过吗？`tail -f ~/.pi-observer/probe.log` |
| 状态栏「累计丢弃」不是 0 | 队列满了或批次被拒，`/api/health` 里的 `recent_problems` 有原因 |
| 「看板服务连接中断」 | 服务没起来或端口变了 |
| 想看服务端的告警 | 服务端日志写 stderr；`/api/health` 的 `recent_problems` 也能看到最近几条 |

## 6. 常见问题

### 6.1 页面不停闪

dev 模式下的现象：整页每隔几百毫秒重载一次。原因是 dev 的文件监听把工程外的文件
（Pi 的会话文件、看板自己的 WAL）当成了源码变化，一变就重编译，重编译完浏览器整页重载。

```bash
# 停掉 dev 服务，删掉构建产物，再起
rm -rf .next && npm run dev
```

桌面应用没有这个问题——它跑的是生产构建，没有热更新。

### 6.2 装了探针但没有请求数据

按顺序查：Pi 会话是不是重开过 → 右上角是不是「探针已连接」→ 有没有模型请求发生过
（没有请求就没有正文）→ `probe.log` 里有没有报错。

### 6.3 双击打不开

右键 →「打开」。见 §2.1。

### 6.4 dev 服务和桌面应用同时开

能共存，两边共用 `~/.pi-observer/observer.db`（SQLite 允许多进程读写）。但
`probe.json` 里记的地址会被**最后启动的那个**改写，探针下次开会话时连的是它。
数据都落在同一个库里，不会丢。

只开一个更省心：开发用 `npm run dev`，平时用桌面应用。

另外，**打包前要停掉 dev 服务**：`next build` 和 `next dev` 共用 `.next` 目录，
同时跑会把 dev 的产物混进打包结果。

### 6.5 误删数据了

正文文件删了就没了——正文是原样落盘的，没有备份机制。索引库没了可以重新扫会话文件重建
（但只有会话条目，请求正文与事件正文找不回来）。

## 7. 给开发者：常用命令

| 命令 | 干什么 |
|:--|:--|
| `npm run dev` | 开发服务（4173） |
| `npm run build` | 生产构建，产物在 `.next/` |
| `npm start` | 跑生产构建 |
| `npm test` | 单元测试（178 项） |
| `npm run typecheck` | 类型检查 |
| `npm run accept` | 离线验收（28 项，跑在临时目录里，不碰真实数据） |
| `npm run verify` | 上面三样一起跑 |
| `node tools/desktop/prepare.mjs` | 构建 + 裁剪桌面版的资源 |
| `cd desktop && npm run dmg` | 打出 `.app` 与 `.dmg` |
| `node tools/flicker-probe.mjs` | 诊断闪屏：区分「整页重载」和「局部重渲染」 |
| `node tools/shot.mjs <目录> <地址>` | 给页面拍桌面宽度的截图 |
